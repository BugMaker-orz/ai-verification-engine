# AI 验真引擎 — 零基础使用指南

> 这份文档写给完全不会写代码的同学。不需要任何编程基础，照着步骤一步步做就能用。

---

## 一、这个项目是干什么的？

### 一句话说明

你把好几份文件（合同、协议、报告等）丢进去，它自动帮你检查：

1. **文件之间有没有矛盾**（比如一份写金额 28 万，另一份写 32 万）
2. **文件里缺了什么该有的内容**（比如合同里没有写"违约了怎么办"）
3. **文件里有没有不该出现的东西**（比如还有空白没填、"最终解释权归我"这种霸王条款）
4. **格式对不对**（比如日期写没写、电话是不是 11 位）

最后生成一份**检查报告**，告诉你哪里有问题、在第几行、建议怎么改。

### 打个比方

就像你请了一个特别细心的律师助理，把你一摞合同翻来覆去对比一遍，然后递给你一张清单："第 3 份合同第 12 行的金额和第 1 份对不上，建议核对。"

### 它能检查什么文件？

- PDF 文件（`.pdf`）
- Word 文件（`.docx`）
- 纯文本文件（`.txt`）

## 二、你需要准备什么？

### 1. 一台能上网的电脑

Windows / Mac / Linux 都行。

### 2. 安装 Python

Python 是一个免费软件，这个项目需要它来运行。

**怎么装：**
1. 打开浏览器，访问 https://www.python.org/downloads/
2. 点击黄色的 "Download Python 3.x.x" 按钮下载
3. 双击下载的安装包
4. **重要**：安装界面最下方有个 "Add Python to PATH" 选项，**一定要勾选**！
5. 点 "Install Now"，等它装完

**验证装好了没：**
- Windows：按 `Win + R`，输入 `cmd` 回车，在黑窗口里输入 `python --version`，能看到版本号就说明装好了
- Mac：打开"终端"，输入 `python3 --version`

### 3. 下载项目代码

**方法一：用 Git（推荐，方便以后更新）**
- 先装 Git：https://git-scm.com/downloads
- 装好后，在你想放项目的文件夹里，右键选 "Git Bash Here"（Windows）或打开终端（Mac）
- 输入：
  ```
  git clone https://github.com/BugMaker-orz/ai-verification-engine.git
  ```
- 回车，等它下载完

**方法二：直接下载 ZIP（最简单）**
1. 打开 https://github.com/BugMaker-orz/ai-verification-engine
2. 点绿色的 "Code" 按钮
3. 点 "Download ZIP"
4. 下载后解压到你想放的位置

### 4. 安装项目需要的工具

打开命令行（Windows 的 cmd 或 Mac 的终端），进入项目文件夹：

```
cd ai-verification-engine
```

然后输入：

```
pip install -r requirements.txt
```

回车，等它自动安装（可能需要 1-2 分钟）。看到 "Successfully installed" 就好了。

## 三、第一次使用（推荐：网页界面，不用敲命令）

### 第 1 步：启动网页界面

打开命令行（Windows 的 cmd 或 Mac 的终端），进入项目文件夹，输入：

```
python app.py
```

回车后，等几秒钟，浏览器会**自动打开**一个网页，地址是 http://127.0.0.1:7860

如果浏览器没自动打开，手动复制这个地址到浏览器里打开就行。

### 第 2 步（可选）：配置 AI 语义增强

网页最顶部有一个"🤖 AI 设置（可选 — 配置后启用语义增强）"的折叠面板，点击展开。

里面有三个输入框：

| 输入框 | 填什么 | 示例 |
|--------|--------|------|
| API 地址 | AI 服务的接口地址 | `https://api.deepseek.com/v1` |
| API Key | 你的 API 密钥（密码形式输入） | `sk-xxxxxxxx` |
| 模型名 | 用哪个模型 | `deepseek-chat` |

填完后：
1. 点"🔌 测试连接"——如果显示绿色"连接成功"就说明配置对了
2. 点"💾 保存配置"——以后打开网页会自动加载，不用重复填

**配置了 AI 有什么用？**
- 条款匹配更智能（不只是找关键词，能理解语义）
- 冲突检测更准确（排除"表述不同但意思一样"的误报）
- 补位建议更具体（AI 会根据你的文档内容给出修改建议）
- 报告会多一段"AI 总体评价"

**不配置 AI 能用吗？** 完全可以。不配置时自动使用"基础规则匹配"模式，所有功能正常，只是没有语义增强。

> **支持哪些 AI 服务？** 所有兼容 OpenAI 接口格式的服务都能用，包括 DeepSeek、通义千问、豆包、OpenAI、本地部署的模型等。只需填对应的 API 地址和模型名。

### 第 3 步：上传文件

网页左边有一个上传区域，写着"将文件拖放到此处 - 或 - 点击上传"。

- **方法一**：直接把你要检查的文件拖进去
- **方法二**：点击上传区域，在弹出的窗口里选择文件

可以一次选多个文件（按住 Ctrl 键点选）。

### 第 4 步：选择规则库

上传区域下面有个下拉菜单"检查规则"，默认是 `general_contract.yaml`（通用合同规则）。一般不用改，直接用默认的就行。

如果你为其他类型的文件建了专门的规则库，在这里选对应的。

### 第 5 步：输入报告名称（可选）

再下面有个"报告文件名"输入框，可以随便起个名字，比如"2024合同检查"。不填也可以，默认叫 `verification_report`。

### 第 6 步：点击"开始验真"

点击蓝色的"🚀 开始验真"按钮，等几秒钟。

### 第 7 步：看结果

网页右边会显示：

- 📊 **大评分**：100 分制，A 最好，F 最差，颜色区分
- 📋 **问题统计**：严重/高/中/低各多少个，冲突多少，欠缺多少
- ⚠️ **跨文件冲突**：每条冲突标了严重度、来自哪份文件、第几行
- 📝 **欠缺与违规**：每条都有补位建议（绿色框）
- 📥 **下载报告**：最下面可以下载 HTML 报告（浏览器打开看）和 Markdown 报告（可编辑）

### 关闭网页界面

用完后，回到命令行窗口，按 `Ctrl + C` 就关掉了。

## 四、命令行方式（备选，适合熟练后用）

如果你不想用网页界面，也可以用命令行。

### 第 1 步：把你要检查的文件准备好

比如你要检查 3 份合同，把它们放在一个文件夹里，比如：

```
D:\我的文档\合同检查\
├── 主合同.pdf
├── 补充协议.docx
└── 附件.txt
```

**记住这个文件夹的路径**，等下要用。

### 第 2 步：打开命令行，进入项目文件夹

Windows：在项目文件夹里，按住 `Shift` 键 + 鼠标右键，选 "在此处打开 PowerShell 窗口" 或 "在终端中打开"。

Mac：打开终端，输入 `cd ` （注意 cd 后面有空格），然后把项目文件夹拖进终端窗口，回车。

### 第 3 步：运行检查命令

复制下面这行，把文件路径换成你自己的：

```
python cli.py -r rules/general_contract.yaml -f "D:\我的文档\合同检查\主合同.pdf" "D:\我的文档\合同检查\补充协议.docx" -o output/ -n 我的检查报告
```

**各部分是什么意思：**

| 部分 | 意思 | 你需要改吗 |
|------|------|-----------|
| `python cli.py` | 启动程序 | 不用改 |
| `-r rules/general_contract.yaml` | 用哪套检查规则 | 一般不用改（通用合同规则） |
| `-f 文件1 文件2 ...` | 你要检查哪些文件 | **换成你的文件路径** |
| `-o output/` | 报告存在哪里 | 可以改成你想要的文件夹 |
| `-n 我的检查报告` | 报告叫什么名字 | 随便起 |

**提示：**
- 文件路径如果有空格或中文，用**英文双引号**包起来，比如 `"D:\我的文件\合同.pdf"`
- 可以一次检查任意多个文件，用空格隔开
- 路径不会写？把文件直接拖进命令行窗口，它会自动帮你填好路径

### 第 4 步：看结果

命令跑完后，会在项目的 `output/` 文件夹里生成两个文件：

```
output/
├── 我的检查报告.html    ← 用浏览器打开，好看的可视化报告
└── 我的检查报告.md      ← 纯文本报告，可以用记事本打开
```

**双击 `.html` 文件**，它会用浏览器打开，你能看到：

- 📊 **总体评分**：100 分制，A 最好，F 最差
- 📋 **检查了哪些文件**
- 🔍 **每个文件提取出了什么信息**（甲方是谁、金额多少、日期等）
- ⚠️ **文件之间的矛盾**（会标出来自哪份文件、第几行）
- 📝 **缺了什么、多了什么**（每条都有修改建议）

## 五、怎么改检查规则？

检查规则写在一个叫 `rules/general_contract.yaml` 的文件里。**用记事本就能打开编辑**，不需要写代码。

### 这个文件长什么样？

打开后你会看到类似这样的内容：

```yaml
fields:
  - name: "甲方/委托方"
    required: true
    patterns:
      - "甲方[:：]\\s*(.+)"
```

别怕，我来翻译：

- `fields:` = 下面是要检查的"字段"（就是要从文件里找什么信息）
- `name: "甲方/委托方"` = 这个字段叫"甲方/委托方"
- `required: true` = 这个字段必须有，没有就报错（改成 `false` 就是不强制）
- `patterns:` = 怎么在文件里找到它（用关键词匹配，比如找"甲方："后面的内容）

### 常见修改操作

#### 修改 1：某个字段不想强制检查了

找到那个字段，把 `required: true` 改成 `required: false`。

比如你觉得"联系电话"不一定每个合同都有：
```yaml
  - name: "联系电话"
    required: false    ← 改成 false
```

#### 修改 2：加一个新的要检查的字段

比如你想检查"项目编号"，在 `fields:` 下面加一段：

```yaml
  - name: "项目编号"
    required: true
    patterns:
      - "项目编号[:：]\\s*(.+)"
      - "项目编号[:：]\\s*([A-Z0-9-]+)"
    description: "项目的唯一编号"
```

**怎么写 patterns（匹配规则）：**
- 最简单的写法：`"关键词[:：]\\s*(.+)"`
- 把"关键词"换成你要找的词，比如要找"质保期"就写 `"质保期[:：]\\s*(.+)"`
- 程序会自动提取关键词后面的内容

#### 修改 3：加一个"必须有的条款"

比如你想确保合同里一定有"质保条款"，在 `clauses:` → `required:` 下面加：

```yaml
    - id: "C-REQUIRED-007"
      name: "质保条款"
      keywords: ["质保", "保修期", "质量保证", "售后"]
      severity: "medium"
      description: "合同应该写质保多久、坏了谁负责"
```

- `keywords:` = 出现这些词中的任意一个，就算有这个条款
- `severity:` = 严重程度，`critical`（最严重）/ `high` / `medium` / `low`
- `id:` = 编号，别和已有的重复就行

#### 修改 4：加一个"不能有的内容"

比如你想检查合同里有没有"最终解释权归我方"这种霸王条款，在 `clauses:` → `forbidden:` 下面加：

```yaml
    - id: "C-FORBIDDEN-004"
      name: "最终解释权条款"
      keywords: ["最终解释权", "解释权归"]
      severity: "high"
      description: "这种条款可能无效，建议删除"
```

#### 修改 5：加一个"文件之间要一致"的检查

比如你想确保多份文件里的"项目编号"都一样，在 `cross_document:` 下面加：

```yaml
  - id: "X-DOC-007"
    name: "项目编号一致性"
    fields: ["项目编号"]
    severity: "high"
    description: "所有文件里的项目编号应该相同"
```

**注意：** `fields: ["项目编号"]` 里的"项目编号"必须和你在上面 `fields:` 里定义的字段名**完全一样**。

### 改完之后

保存文件，重新运行检查命令就行，不用做别的。

## 六、为不同类型的文件建不同的规则

现在只有一套"通用合同"规则。如果你要检查别的类型的文件（比如 ESG 报告、招投标文件），可以复制一份规则文件改名：

1. 复制 `rules/general_contract.yaml`，改名叫 `rules/招投标文件.yaml`
2. 用记事本打开，把里面的字段和条款改成招投标相关的
3. 运行时指定新规则：
   ```
   python cli.py -r rules/招投标文件.yaml -f 招标文件.pdf 投标文件.pdf -o output/
   ```

## 七、常见问题

### Q1：运行后报错 "No module named 'xxx'" 怎么办？

说明依赖没装好。重新运行：
```
pip install -r requirements.txt
```

### Q2：PDF 文件检查不出内容？

可能是扫描件（图片版 PDF）。这个项目目前只能读**有文字层**的 PDF。扫描件需要先 OCR 识别成文字。

### Q3：中文路径报错？

把文件路径用英文双引号包起来，比如：
```
-f "D:\我的文件\合同.pdf"
```

### Q4：报告在哪里？

在你用 `-o` 指定的文件夹里。如果没指定，默认在项目的 `output/` 文件夹。

### Q5：怎么知道检查得准不准？

建议先用一份你已经人工检查过的文件跑一遍，对比结果。规则库里的关键词可以根据你的实际文件调整，越用越准。

### Q6：评分是怎么算的？

满分 100 分，发现问题就扣分：
- 严重问题（critical）：扣 25 分
- 高（high）：扣 10 分
- 中（medium）：扣 4 分
- 低（low）：扣 1 分

等级：90+ = A，80+ = B，70+ = C，60+ = D，60 以下 = F。

### Q7：会泄露我的文件内容吗？

不会。所有检查都在你自己的电脑上运行，文件不会上传到任何服务器。
