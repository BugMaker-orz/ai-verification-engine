# AI 验真引擎 — 技术架构文档

## 1. 系统概述

AI 验真引擎是一个面向多文档场景的自动化验真工具。核心解决三个问题：

1. **字段级对齐拆解**：从非结构化文档（PDF/TXT/DOCX）中提取结构化字段
2. **跨文件冲突定位**：检测多份关联文档之间同字段的不一致
3. **规则驱动欠缺检查**：依据预设规则库查找文件中缺失的字段、条款，以及禁止出现的内容

最终输出带冲突定位、双源依据、补位建议的完整校验报告（Markdown + HTML）。

## 3. 核心模块详解

### 3.1 文件解析器 (parser.py)

**职责**：将不同格式的文件统一转换为 `ParsedDoc` 对象。

**设计要点**：
- 采用策略模式，按扩展名分发到 `_parse_pdf` / `_parse_txt` / `_parse_docx`
- PDF 使用 `pdfplumber`，保留分页信息（`pages` 列表）
- DOCX 同时提取段落文本和表格内容（表格行用 ` | ` 连接单元格）
- 统一编码处理（`errors="replace"` 防止异常字符中断）

**数据结构**：
```python
@dataclass
class ParsedDoc:
    path: str
    filename: str
    file_type: str       # pdf / txt / docx
    text: str            # 全文
    pages: List[str]     # 分页文本
    line_count: int
```

### 3.2 规则引擎 (rules.py)

**职责**：加载 YAML 规则库，提供结构化的规则对象。

**规则类型**：

| 类型 | 类名 | 用途 | 关键字段 |
|------|------|------|---------|
| 字段规则 | `FieldRule` | 定义可提取字段 | name, required, patterns, format |
| 条款规则 | `ClauseRule` | 必含/禁止条款 | id, name, kind, keywords, patterns, severity |
| 跨文档规则 | `CrossDocRule` | 多文档一致性检查 | id, name, fields, severity, normalize |

**严重度分级**：`critical`(4) > `high`(3) > `medium`(2) > `low`(1) > `info`(0)

**字段提取逻辑**：
- 遍历 `patterns` 列表，任一正则匹配即提取
- 优先取第一个非空捕获组，否则取整个匹配
- 支持可选捕获组（不会因组为空而返回 None）

### 3.3 字段提取器 (extractor.py)

**职责**：从单份文档中按规则库提取全部字段，并做格式校验。

**格式校验器**：
- `date`：匹配 `YYYY-MM-DD` / `YYYY年MM月DD日` 等
- `currency`：匹配带符号/单位的金额
- `email` / `phone` / `id_card`：标准格式正则

**行号定位**：提取值后在原文中查找第一次出现的行号，用于报告中的精确定位。

### 3.4 冲突检测器 (conflict.py)

**职责**：检测多份文档之间同字段的不一致。

**核心算法 — `_values_conflict(v1, v2, field_name)`**：

1. **归一化预处理**：去空白、全角转半角、统一大小写
2. **精确匹配**：归一化后相同则不冲突
3. **数值型字段**（含"金额/数量/期限"等关键词）：
   - 提取数值（支持千位逗号、小数）
   - 数值差 < 1e-6 则不冲突
4. **日期型字段**（含"日期/时间"）：
   - 提取日期，归一化为 `Y-M-D`（去年月日前导零）
   - 归一化后相同则不冲突
5. **文本型字段**：归一化后不同即冲突

**数值提取修复**：正则 `-?\d{1,3}(?:,\d{3})+(?:\.\d+)?|-?\d+(?:\.\d+)?`
- 第一个分支要求至少一个千位逗号（`+`），避免对无逗号数字只匹配前3位
- 第二个分支匹配普通连续数字

**冲突类型**：
- `value_mismatch`：值不一致
- `missing_in_one`：某文档缺失该字段

### 3.5 欠缺检查器 (gap.py)

**职责**：依据规则库检查单份文档的欠缺与违规。

**检查项**：

| 类型 | kind | 触发条件 | 严重度 |
|------|------|---------|--------|
| 必填字段缺失 | `missing_field` | required=True 但未提取到 | high |
| 字段格式不合法 | `format_invalid` | 提取到值但格式校验失败 | medium |
| 必含条款缺失 | `missing_clause` | 关键词/正则均未匹配 | 规则定义 |
| 禁止条款出现 | `forbidden_clause` | 关键词/正则匹配成功 | 规则定义 |

**补位建议**：每项欠缺自动生成建议文本，基于规则的 description 和字段 format。

### 3.6 报告生成器 (report.py)

**职责**：将验真结果渲染为 Markdown 和 HTML 报告。

**验真评分算法**：
```
score = max(0, 100 - Σ weights[severity])
weights = {critical: 25, high: 10, medium: 4, low: 1, info: 0}
grade = A(≥90) / B(≥80) / C(≥70) / D(≥60) / F(<60)
```

**报告结构**：
1. 验真概览（评分、等级、问题统计、文档清单）
2. 字段提取结果（每份文档的字段表）
3. 跨文件冲突定位（每项冲突：严重度、描述、双源依据）
4. 欠缺与违规检查（每项：严重度、位置、补位建议）
5. 规则集说明

**HTML 报告特性**：
- 响应式布局，卡片式设计
- 严重度颜色标签（红/橙/黄/蓝/灰）
- 评分等级颜色（A绿/B蓝/C黄/D橙/F红）
- 补位建议绿色高亮框

### 3.7 主引擎 (engine.py)

**职责**：编排完整验真流程，提供统一 API。

**流程**：
```
verify(file_paths):
  1. docs = parse_files(file_paths)           # 解析
  2. doc_fields = extract_all(docs, ruleset)  # 字段提取
  3. conflicts = detect_conflicts(doc_fields)  # 冲突检测
  4. gaps = check_all(docs, doc_fields)        # 欠缺检查
  5. return VerificationResult(...)             # 组装结果
```

## 4. 规则库设计

### 4.1 通用合同规则集 (general_contract.yaml)

**字段规则（10条）**：文档标题、甲方/委托方、乙方/受托方、签订日期、生效日期、合同金额、付款方式、合同期限、联系人、联系电话

**必含条款（6条）**：违约责任、争议解决、保密、不可抗力、合同解除/终止、知识产权

**禁止条款（3条）**：空白占位符未填写（critical）、不平等格式条款单方免责（high）、模糊金额表述（medium）

**跨文档规则（6条）**：甲方名称、乙方名称、合同金额、签订日期、生效日期、合同期限一致性

### 4.2 扩展规则集

可按行业创建新的 YAML 文件，如：
- `rules/esg_report.yaml` — ESG 报告验真
- `rules/bidding.yaml` — 招投标文件验真
- `rules/enterprise_qualification.yaml` — 企业资质文件验真

## 5. 测试覆盖

`tests/test_engine.py` 包含 7 项测试：

1. **规则集加载**：验证字段/条款/跨文档规则数量
2. **文件解析**：验证 TXT 解析行数和内容
3. **字段提取**：验证甲方/乙方/日期/金额提取正确性
4. **值冲突逻辑**：数值/日期/文本的冲突判断边界
5. **跨文件冲突检测**：验证示例文档间检测到的冲突字段
6. **欠缺检查**：验证补充协议中缺失的条款和禁止条款
7. **完整引擎端到端**：验证评分、冲突数、欠缺数、报告生成

## 6. 已知限制与扩展方向

### 当前限制
- 条款匹配基于关键词/正则，不支持语义级理解（如同义表述）
- PDF 解析依赖文本层，扫描件 PDF 需先 OCR
- 不支持 Excel/CSV 表格类文件
- 冲突检测仅支持同字段比对，不支持跨字段逻辑校验（如"金额=单价×数量"）

### 扩展方向
1. **LLM 语义增强**：接入大模型 API 做条款语义冲突检测和缺失推断
2. **Web UI**：Gradio/Streamlit 拖拽上传，实时展示结果
3. **规则编辑器**：可视化配置规则库，无需手写 YAML
4. **OCR 集成**：支持扫描件 PDF 的文字识别
5. **跨字段逻辑校验**：支持用户定义字段间的计算关系校验
6. **PDF 报告导出**：HTML 转 PDF，便于归档
7. **多语言支持**：英文合同规则库
